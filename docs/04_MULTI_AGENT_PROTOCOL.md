# Scoped review and change workflow

Bind the actual repository heads, current owner amendments and permitted work.
Use the AF-review and AOD guidance in
[aod-skills](https://github.com/rpoyau/aod-skills) for review ownership and
persistent source-bound records. Historical request bundles do not authorize a
new mutation, merge, conversion or physical claim.

1. Inventory the publication drivers, scientific inputs and changed paths.
   `digest` provides a recursive index; `labels` provides a supported literal
   driver scan. Their coverage differs and neither is a compiled proof graph.
2. Inspect the diff with its actual consumers and premises. Use `slice --files`
   when a diff includes moves without hunks. Keep non-TeX/Typst dependencies
   accessible to reviewers even though the slicer cannot interpret them.
3. Give each reviewer a bounded question, source binding, relevant premises and
   evidence class. Agreement between agents is not independent scientific proof.
4. Separate review findings from authorized repair. Preserve scientific source
   identities and stable references; keep task narratives outside scientific
   execution. A naming cleanup must not invent new laws or duplicate chapters.
5. Run the affected repository checks, exact fixtures where applicable, builds
   and rendered-page checks. Report actual outcomes and untested claims. A clean
   lexical scan and green CI do not settle every AF rubric question.

Parallel tasks should have disjoint edit ownership and explicit integration.
Resolve missing user intent with concise questions when needed; do not convert
ordinary preferences into axioms. Follow the user's authorized delivery scope.
No automatic merge, LaTeX-to-Typst conversion, or universal Main freeze follows
from this workflow.
